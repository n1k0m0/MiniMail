# Source security and performance review — 2026-10-29

## 2026-10-30 backup/notification extension

The optional full-backup host service is a privileged trust boundary. Its fixed Unix socket requires an installation token and only accepts bounded export requests for the configured root; it never accepts commands, output paths or remote destinations. The web layer requires an authenticated administrator, password, single-use fresh TOTP and pause consent before starting a job. Listing/downloads are bound to that session and credential state; unauthorized roles do not contact the host service. Downloads stream encrypted files, including byte ranges. Passwords exist only in process memory; private job metadata contains no password. Updater/daemon locks prevent concurrent update/export and duplicate daemon instances. Enabling the read-only control mount has a durable rollback journal and preserves protected configuration. Restart recovery resumes a paused app and fails interrupted jobs; only completed encrypted artifacts are downloadable. Three jobs and 24-hour expiry bound retention. Socket/token runtime files and prior archives are excluded from full archives. The systemd service runs as the installation owner with existing Docker privileges; the app receives no Docker socket or general host access. Recovery remains a host-only action into empty resources.

Browser notifications are opt-in and isolated by user/browser, with permission denial handled explicitly. No third-party push service receives mail/calendar data. Pop-ups contain no message body, subject or event title. UIDNEXT observation avoids treating unread flag changes as arrivals and establishes a silent initial baseline. Shared browser locks/claims suppress duplicate tab notifications; snoozed calendar occurrences receive distinct identities. Background polling remains bounded to existing mailbox checks and one-minute calendar checks, subject to browser throttling. All pop-up actions check that the same user is still active.

This review covers the server and API routes, React frontend, mail and calendar parsers, cryptographic operations, database access and migration, VPN proxy, Docker configuration, installation scripts, CI and dependency tree. The baseline is commit `31b8d28`. Findings below describe that baseline; their fixes are included with this report.

Severity reflects this application's trust boundaries and the prerequisites described below. This is a source review with synthetic regression tests, not an external penetration test or certification. Live mail delivery, third-party provider behavior and host/reverse-proxy configuration are outside the validation scope. No production messages, passwords or calendar data are used as fixtures.

## Performance and correctness fixes

- **Long conversations:** recursive union/find overflowed the JavaScript stack on a synthetic chain of 30,000 messages. Iterative path compression and union by size handle that case while preserving message ordering and unread filtering.
- **Password creation/reset:** synchronous scrypt blocked the HTTP event loop. Hash creation and verification now share an asynchronous, four-operation limit. Existing stored hashes remain compatible. Password changes use a conditional update and transaction so a concurrent reset cannot be overwritten using an earlier credential snapshot.
- **Calendar imports:** local imports previously started a worker and recalculated storage use per entry. They now validate the entire input in one bounded worker, calculate the budget once, and write batches of at most 100 entries in one transaction. The 250-entry regression fixture uses three insert statements; duplicate imports are skipped, and an injected second-batch failure leaves the original records unchanged.
- **Calendar synchronization:** cached entries are fetched once, and unchanged event content is not re-encrypted or rewritten. A 100-entry unchanged subscription uses one cache read and zero event writes while preserving ciphertext, timestamps and versions. Provider metadata changes still update the relevant fields.
- **Initial page load:** the mail-route world map and geometry libraries load only when the map is opened. The initial production JavaScript bundle falls from **529.64 kB to 394.34 kB**; gzip falls from **171.44 kB to 120.21 kB**. Calendar code remains separately loaded. These are build artifact sizes, not browser timing measurements.

## Operating limits and follow-up

The app server holds the decryption key for stored credentials and private mail keys. It must be trusted; encrypted storage does not protect against a compromised app host. Contact names/addresses and other relational metadata are not all encrypted columns. Back up the original encryption key privately with the database.

Allowlisted private mail/calendar hosts and the administrator-selected AI endpoint intentionally cross the default outbound-network boundary. Keep allowlists narrow and enforce container/network egress rules as appropriate. This update does not configure host firewalls or change production provider credentials.

Remote multi-item calendar imports cannot be rolled back atomically on a third-party server. Check the destination after a provider error before retrying. OpenPGP memory limits are per operation, not a process-wide memory/CPU sandbox; very large or deliberately expensive cryptographic inputs and large mail indexes still justify container resource limits and monitoring. Login rate limits are process-local and reset when the app restarts.

Automated checks include the full test suite against an isolated MySQL 8.4 database, frontend production build, dependency audit, installer checks and Compose validation. Frontend verification covers component rendering and the production build; no live-browser visual check is claimed.
